# Checklist — Retrospectiva

## Bem feito quando

- [ ] Abriu conferindo a ação da retro anterior, com número.
- [ ] Todos escreveram antes de falar (por carta ou pulso); não foi o líder sozinho.
- [ ] Começou pelo que foi bem.
- [ ] Cada item de "Melhorar" é uma situação com fonte (ID do cartão, dias, arquivo), não um nome.
- [ ] As ideias passaram pelo filtro: sob controle do time, cabe num ciclo, atrito repetido.
- [ ] Saiu **uma** ação, com um dono e uma data.
- [ ] A ação tem "como medimos" com número de hoje.
- [ ] O PDCA foi aberto com o Plan preenchido.
- [ ] As ideias que sobraram foram para o estacionamento sem promessa.
- [ ] Nenhum assunto de produto (isso era da review).
- [ ] Durou até 30 minutos; clima amistoso.

## Erros comuns (da aula)

- Desabafo sem ação (v6 aula 08).
- Lista de doze melhorias; "1 ou 2 experimentos" — duas viram nenhuma.
- Caça ao culpado; falar de pessoa em vez de situação (M06 A08, M07 A12).
- Assunto que cabia na review.
- Ação que depende de outra área ou do dirigente responsável (não está sob controle do time).
- Ação sem data ("em breve") — o exemplo v6 comete esse erro.
- Não fechar a ação anterior — a melhoria fica aberta para sempre (v6 A01).
- Pular a retro quando a semana foi ruim — é quando ela mais vale (M07 A01).

## Formas de saída

- [ ] Entrega no formato pedido, conforme [entrega-editavel.md](entrega-editavel.md), salva e conferida; nas revisões, mesmo documento e edições humanas preservados.
- [ ] Quando houver fonte Markdown para canvas, âncoras `<!-- c:id -->` intactas; HTML não é cópia obrigatória.
- [ ] Se pediram o canvas: IDs intactos, nenhum `{{` sobrando, campos completos, sem estouro e uma página, conferidos no arquivo entregue.
