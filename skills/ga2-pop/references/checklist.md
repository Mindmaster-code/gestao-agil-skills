# POP — checklist de "bem feito" e erros comuns

Fonte: M04 A12 (questionar o processo), M04 A13 (POP), canvas legado `Canvas POP.pdf`, exemplo da aula (APPROJ001),
Kit Implementação (POP-SEP-001).

## Bem feito

**É caso de POP?**
- [ ] É processo (repete, sem data fim), não projeto nem produto.
- [ ] É o gargalo achado no briefing — não a operação inteira.
- [ ] Cada etapa foi questionada: "por que existe? quem usa?" O que ninguém usa saiu.

**Cabeçalho**
- [ ] Nome que todo mundo conhece; código mnemônico; data; versão.
- [ ] Área / empresa declarada.

**Corpo**
- [ ] Objetivo diz o resultado, não "padronizar".
- [ ] Escopo tem "cobre" e "não cobre".
- [ ] Cada papel tem uma responsabilidade; há um dono do processo; há quem aprova exceção.
- [ ] Entrada é um gatilho observável (evento, insumo, data).
- [ ] Passos numerados, um verbo cada, com responsável e o que sai; nada depende de "bom senso".
- [ ] Saída é algo que existe no fim e não existia no começo.
- [ ] Pelo menos um indicador de adesão e um de resultado, com base, meta, frequência e onde ver.
- [ ] Todo sistema citado tem "como acessar" (sem segredo escrito).
- [ ] Exceções com tratamento e aprovador.
- [ ] Riscos com mitigação; monitoramento com quem e quando.
- [ ] Aprovação com nome, cargo e data; próxima revisão marcada.

**Teste**
- [ ] Alguém que nunca fez executou só com o POP e chegou à mesma saída.
- [ ] Onde travou, o POP foi corrigido.
- [ ] Cabe em uma página (canvas) ou em duas telas; manual longo não é POP.

## Erros comuns

| Erro | Onde a aula fala | Como recusar |
|---|---|---|
| Manual de 40 páginas | Kit | "Qual é o gargalo? POP é dele, não da operação." |
| Passo sem responsável | A13 | "Quem faz o passo 3? 'Todo mundo' é ninguém." |
| Sistema sem instrução de acesso | A13 | "Como a pessoa nova entra?" |
| Sem versão nem aprovação | A13 (canvas: Data \| Código \| Versão; Aprovação) | "É rascunho. Quem aprovou, quando?" |
| Processo que ninguém questionou | A12 (a planilha de 2–3 h que ninguém lia) | "Quem usa a saída? Por que existe?" |
| Processo "que não dá para medir" | A12 — "todo processo pode ser medido" | "Qual indicador de adesão? Qual de resultado?" |
| Indicador de esforço | v6 04 (vale para todo número) | "POPs escritos não é resultado. O erro caiu?" |
| Objetivo = "padronizar" | A13 (finalidade: direcionamento claro) | "Padronizar para quê? Qual resultado?" |
| Checklist que vira carimbo | Kit, risco 2 | "Qual saída visível denuncia o pulo?" |
| Gatilho "quando der" | canvas: "descreva como o processo inicia" | "O que faz começar? Evento, data, insumo." |
| POP sem teste com quem nunca fez | Passo 2, critério de bem feito | "Quem executou só com o POP? Onde travou?" |
| Segredo escrito no POP | regra de segurança desta adaptação | "Nunca. Aponta onde o acesso é pedido." |

## Formas de saída

- [ ] Formato e destino seguem o pedido ou o documento existente, conforme [Entrega editável](entrega-editavel.md).
- [ ] A entrega foi reaberta e conferida; conteúdo, campos, responsáveis, datas, fontes e edições humanas foram preservados.
- [ ] Se houver Markdown, as âncoras `<!-- c:id -->` estão intactas. Se houver HTML, ele deriva da fonte atual.
- [ ] Se pediram canvas, o modelo correspondente foi usado: IDs intactos, nenhum `{{` residual, sem estouro e uma página quando exigida.
