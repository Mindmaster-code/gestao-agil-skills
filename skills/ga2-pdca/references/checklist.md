# Checklist — PDCA

## Bem feito quando

- [ ] O P tem um fato com número de hoje, sem culpado.
- [ ] A causa raiz está escrita (5 porquês ou link para o A3) e mora no processo.
- [ ] A linha de base foi escrita **antes** do Do.
- [ ] Uma ação só; mais de um passo → 5W2H anexo.
- [ ] Dono único e prazo com data.
- [ ] O Do tem prova pelo caminho real (commit, carta, log, arquivo).
- [ ] O Check mede o **mesmo número** do P, na mesma fonte.
- [ ] O Act tem um verbo: padronizar / ajustar / descartar.
- [ ] Se padronizou, diz onde o padrão foi escrito (POP, política, cadência).
- [ ] Se ajustou, o ciclo nº subiu e o novo P está escrito.
- [ ] O registro de ciclos tem data em cada linha.

## Erros comuns (da aula e da aplicação do laboratório)

- Check por sensação, sem número (M07 / v6).
- Act que não padroniza: "funcionou" e ninguém escreveu onde (v6 A04).
- PDCA que não acaba nunca — sem data de fechamento do ciclo.
- Pular o Check e abrir outro Plan.
- Plano sem linha de base (M02 A07: o plano **é** a linha de base).
- Duas mudanças no mesmo ciclo — não se sabe qual funcionou.
- Confundir com A3: o A3 diagnostica; o PDCA roda. Se há A3, o PDCA aponta para ele.
- Causa raiz que é pessoa.

## Formas de saída

- [ ] Entrega no formato pedido, conforme `entrega-editavel.md`, reaberta e conferida. Documento: Word/Docs; planilha: Excel/Sheets; PDF para leitura; HTML para visualização ou quando pedido. Sem cópias Markdown e HTML obrigatórias.
- [ ] No fluxo Markdown, âncoras `<!-- c:id -->` intactas; qualquer exportação veio da fonte atual.
- [ ] Se pediram o canvas: cópia do modelo público conferida, com IDs intactos, nenhum `{{` sobrando, sem estouro e uma página.
