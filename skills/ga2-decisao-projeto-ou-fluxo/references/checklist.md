# Decisão Projeto ou Fluxo — checklist de "bem feito" e erros comuns

Fonte: M06 A11, v6 Passo 4 aula 00 (slides 04, 07, 08) e aula 06 (urgência), canvas v6 e legado Mod 04 artefato 11.

## Bem feito

**Antes**
- [ ] A iniciativa já foi classificada (projeto / processo / produto) e tem Backlog 2D ou fila.
- [ ] Todos os trabalhos da pessoa ou área estão listados nas duas colunas — o que tem fim e o que chega todo dia.

**Decisão**
- [ ] As três perguntas foram respondidas por trabalho (fim claro? prever a semana? mudança espera?).
- [ ] A trilha foi escolhida pelo trabalho, não pela equipe.
- [ ] Híbrido diz qual trabalho roda em qual trilha.
- [ ] Cada trabalho tem trilha própria; nenhum ficou "nos dois".

**Acompanhamento**
- [ ] Ciclos: duração, meta escrita, diária (dia, hora, lugar), review e retrô (dia, hora).
- [ ] Fluxo: limite por etapa, cartão mais velho, triagem da fila; diária e retrô mantidas.
- [ ] O que se mede está escrito: meta × entregue (ciclo) ou tempo de fila / cartão mais velho / vazão (fluxo).

**Regra**
- [ ] Linha 5 escrita antes do ciclo 1: o que nunca espera, o que nunca entra no meio da semana, quem cede quando a fila estoura.
- [ ] Política de urgência: o que é urgente, quem chama (uma pessoa), quantas por vez (uma), o que acontece com o pausado, onde está escrito.
- [ ] Data de revisão da folha marcada.

**No laboratório**
- [ ] Trilha registrada no portfólio, por frente.
- [ ] Trabalho em ciclo entrou no plano de segunda; trabalho em fluxo tem limite e entra na varredura diária.

## Erros comuns

| Erro | Onde a aula fala | Como o Gestor recusa |
|---|---|---|
| Fila e projeto no mesmo plano de semana → "ciclo não funciona" | v6 aula 00, slide 04 | "A fila estourou a meta. Separa as trilhas antes de julgar o ciclo." |
| Escolher pela equipe ("suporte é tudo fluxo") | v6 aula 00 | "Qual trabalho? O repositório da Ana tem fim — é projeto." |
| Operação contínua tratada como projeto (esperar que acabe) | Base do método: Passo 2 — Organizar o Trabalho §4.4 | "Isso termina quando? Se nunca, é fluxo." |
| Projeto tratado como processo (nunca fecha) | Base do método: Passo 2 — Organizar o Trabalho §4.4 | "Qual é a entrega final? Data?" |
| Fluxo sem limite por etapa | v6 aula 02 — "tudo em andamento, nada pronto" | "Quantos cabem em Fazendo? Quem olha o cartão mais velho?" |
| Folha sem a linha 5 | v6 slide 08 | "Quem cede quando os dois brigam pelo mesmo dia?" |
| Acompanhamento sem dia, hora e lugar | canvas v6, campo 4 | "Diária que dia, que hora, onde?" |
| Ciclo confundido com prazo do projeto | v6 aula 02 | "A iniciativa leva seis semanas; o ciclo é de uma." |
| Ciclo de mais de 4 semanas | M06 A11 | "Não mais que quatro, para não perder o foco." |
| Urgência sem política: todo mundo chama, várias por vez | v6 aula 06 | "Quem pode chamar? Uma por vez. O pausado ganha marca." |
| Confundir com a classificação 3 Ps | Base do método: Passo 2 — Organizar o Trabalho §2.8 | "3 Ps escolhe o briefing; esta folha escolhe como executar." |
| Trilha decidida e não registrada no quadro | laboratório (registro do portfólio na pasta do caso) | "Onde está escrito? Estado vem de arquivo, não de memória." |

## Formas de saída

- [ ] Entrega no formato pedido, conforme [entrega-editavel.md](entrega-editavel.md), salva e conferida; nas revisões, mesmo documento e edições humanas preservados.
- [ ] Quando houver fonte Markdown para canvas, âncoras `<!-- c:id -->` intactas; HTML não é cópia obrigatória.
- [ ] Se pediram o canvas: IDs intactos, nenhum `{{` sobrando, campos completos, sem estouro e uma página, conferidos no arquivo entregue.
