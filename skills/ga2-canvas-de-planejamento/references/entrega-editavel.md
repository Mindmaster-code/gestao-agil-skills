# Entrega editável dos artefatos GA2

## Escolha do formato

O pedido do usuário define formato e destino. Use o formato do documento existente nas revisões.
Sem escolha explícita, siga o padrão indicado na skill: documento `.docx`, planilha `.xlsx` ou visual HTML.
Use Google Docs ou Google Sheets quando o usuário escolher esse destino ou o projeto já trabalhar nele.
Uma pergunta ou análise no chat não obriga criar arquivo. CNV permanece no chat até haver pedido para salvar.

| Necessidade | Entrega |
|---|---|
| Documento para editar e compartilhar | `.docx` ou Google Docs nativo |
| Acompanhar linhas, cálculos e tarefas | `.xlsx` ou Google Sheets nativo |
| Quadro, canvas ou explicação visual | HTML; exportação editável quando solicitada |
| Fonte para automação e versionamento | Markdown, quando o fluxo precisar ou o usuário pedir |

Gere somente os formatos necessários. HTML e Markdown não são anexos obrigatórios de um Word ou Google Doc.
Preserve os campos, a ordem, as regras e a procedência do template da skill em qualquer formato.
Uma planilha do Backlog 2D deve preservar etapas, entregas, tarefas e o recorte do primeiro ciclo.
Word e Docs devem usar títulos, listas e tabelas editáveis; uma imagem do canvas não substitui conteúdo editável.
Quando um canvas oficial for solicitado, preserve seu modelo. Explique diferenças de disposição na exportação para documento.

## Como gerar

A skill de gestão define o conteúdo. Use a capacidade de arquivos do ambiente para criar Word ou Excel reais.
Quando houver skill de documentos ou planilhas disponível, use-a para formatação e gravação.
Use o template do método como estrutura, com rótulos claros, fontes e números preservados.
Não renomeie HTML, Markdown ou texto para `.docx` ou `.xlsx`.

Para Google Docs ou Sheets, use uma integração conectada com escrita no destino escolhido.
Confira as capacidades expostas; o nome do modelo não garante uma integração.
Salvar um `.docx` no Drive não equivale a criar um Google Doc nativo.
Criar o documento não autoriza publicar, enviar mensagens nem ampliar seu compartilhamento.

Se a integração estiver indisponível, entregue `.docx` ou `.xlsx` como alternativa e explique que o Google não foi atualizado.
Se também não puder criar arquivos, forneça conteúdo copiável e identifique a entrega como parcial.
Não invente link nem diga que salvou sem retorno da ferramenta.

## Revisões e fonte do projeto

Leia a versão atual do documento ou planilha antes de editar. Reutilize seu caminho ou ID.
Altere apenas o que o pedido exige; preserve edições humanas, comentários, itens concluídos e evidências.
Mantenha IDs dos itens e registre data e resumo das mudanças quando houver acompanhamento contínuo.
Uma revisão não cria outro documento nem outro projeto por padrão.
Em caso de edição concorrente, releia e concilie as mudanças antes de gravar novamente.

O documento escolhido pelo usuário é a fonte operacional. Markdown pode ser a fonte em um fluxo de repositório.
Nunca sobrescreva um documento vivo com uma cópia Markdown antiga.
Se houver exportações, derive-as da versão atual e informe qual documento deve receber as próximas edições.

## Conferência e entrega

- Reabra o arquivo gerado ou releia o documento pela integração.
- Confira conteúdo, campos do método, tabelas, responsáveis, datas, fontes e pontos em aberto.
- Em planilhas, confira fórmulas, tipos de dados e IDs. Não invente valores para completar células.
- Em revisões, confira que o destino e os itens preservados continuam corretos.
- Forneça o arquivo ou link real, o que mudou e qualquer limitação de gravação ou conferência.

Uma conferência estrutural não prova o layout no Word ou no navegador. Informe exatamente o que foi verificado.
